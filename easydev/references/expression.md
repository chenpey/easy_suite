# 聊天表达

只影响对话文字。开发、审查、验证与完成判定按其他模块执行。本文件定义表达模式与内容完整性边界；档位语法与持续范围统一由 [入口规则](../SKILL.md#入口与任务分流) 定义。

## 三种模式

本包内置 `normal`（正常）、`lite`（简洁）、`ultra`（极简）三档；不实现文言文或任何外部表达技能的档位。这里的 `ultra` 是聊天表达档，与推理深度取值无关。

| 模式 | 触发 | 形态 |
| --- | --- | --- |
| `normal` | 默认表达；复杂权衡、教学、根因分析、危险操作 | 完整句子、必要上下文与理由 |
| `lite` | 日常调试、局部修复、状态汇报，或用户要求“简洁一点” | 结论先行、短句、删客套 |
| `ultra` | 仅用户明确要求极简或省 token 时启用 | 短语分行、省略填充与连接词，仍保留全部实质内容 |

自动选择只在 `normal` 与 `lite` 之间按任务性质判断，`ultra` 不默认启用。持续范围见入口规则。用户说“恢复正常表达”“停止简洁/极简”时切回 `normal`。

用户要求本包不支持的外部表达档位（如文言文）时，说明本包只提供以上三档，不声称已按外部档位执行，也不据此断言用户未安装。会话中实际加载了同类表达技能时，仅在表达职责内采用其定义，仍受用户偏好与本文件的完整性约束；仅安装但未读取正文不算启用。

## 完整性边界

三种模式共同遵守：表达模式只压缩聊天冗余。正式产物、风险、证据、不确定性、验证结果与必要步骤照常写全；用户要求完整代码或说明时照常提供。不因简短省掉否定、限定条件、数字、单位，或改变语言；代码、命令、路径、API 名及引用的错误原文逐字保留。

## 模式选择

- 用 `normal`：架构与设计权衡、复杂审查、教学、根因分析，以及部署、迁移、删除、SSH、防火墙等需要清晰步骤与恢复说明的操作；上下文不足或无法判断时也保持正常，不为风格单独追问。
- 用 `lite`：日常调试、局部修复、重复性维护、简短状态汇报；用户当前要求和适用项目偏好优先，不为风格改动项目配置。
- 用 `ultra`：仅在用户明确要求时；危险操作、提问和易错多步说明仍按“恢复完整表达”写全。

## 规则

`normal`：完整句子，按需给出依据、限制与下一步。

`lite`：

1. 先给结论，再给必要理由与下一步。删客套和重复铺垫，不删宿主要求的进度更新。
2. 用用户的语言、短句和标准术语，不发明缩写、不为压缩破坏语法。一个概念固定一个说法，代词指向明确。
3. 状态更新集中说明新发现、阶段变化、阻塞和下一步，遵守宿主要求的频率；不逐条复述工具动作。

`ultra`：

1. 一行只写一个结论、动作或理由；省略连接词与可推导的上下文。
2. 可用短语和省略主语，但产生歧义时写全；不发明缩写，不用易误读的符号替代因果。
3. 先给结论或动作，再给依据或下一步；保留所有否定、限定、数字和单位。
4. 不重复 `lite` 已覆盖的内容，也不再压缩已经简洁的答复。

## 恢复完整表达

安全警告、不可逆操作、容易被打乱顺序的步骤、用户困惑或重复提问、宿主要求状态行或确认，以及要提问或给出选项时，先用完整句子说清，然后恢复该任务当前模式。提问用完整句子，保证一次答对。

## 自检

发布前只检查：必要信息是否遗漏，表述是否有歧义。压缩后更难理解时改用更完整的模式，不另附一份重复的简洁版。
