# 模型配置

模型配置由代理按以下顺序读取，选择第一个存在的完整文件，不合并多个文件：

1. 用户在当前对话中明确指定的配置文件路径。
2. 用户配置：macOS/Linux 为 `$XDG_CONFIG_HOME/easydev/models.json`（XDG_CONFIG_HOME 非空时），否则为 `~/.config/easydev/models.json`；Windows 为 `%APPDATA%/easydev/models.json`，APPDATA 未设置时使用用户主目录下的 `.config/easydev/models.json`。主目录及环境变量以宿主实际提供的值为准，不能猜测其他用户路径。
3. 没有外部配置时使用包内 [models.json](../models.json)。

分派前报告实际采用的配置路径并读取；选中的外部配置无效或不可读时说明问题，不静默跳回默认配置。用户明确指定的路径不存在也应报错；正常未创建用户配置则使用包内默认值。无法读取用户目录时，说明限制并请用户提供可访问的配置或明确采用默认值。

用户配置放在 Skill 安装目录之外，便于多个 harness 共用，更新 Skill 不会覆盖它。不要自动创建配置或修改宿主设置。配置是由代理解释的路由偏好，不是宿主配置、模型注册表或强制切换模型的运行时插件。

## 字段

- `developer`：开发及修复角色，包含 `model`、`reasoning_effort`。
- `reviewer`：独立审查及复审角色，字段同上。
- `upgrades`：按顺序启用的升级阶段，默认空数组，最多两项；每项都包含完整的 `developer` 和 `reviewer`，避免角色互换时猜测审核者。
- `model: "inherit"`：遵循宿主的模型继承规则，调用时不发送字符串 `inherit` 作为模型 ID。其他值须为宿主实际支持的完整模型 ID。
- `reasoning_effort: "inherit"`：不覆盖推理深度。其他可填写值为 `none / minimal / low / medium / high / xhigh / max / ultra`，实际有效值以所选模型与工具接口为准；配置解析通过不代表模型支持。此处的 `ultra` 是推理深度取值，与 [实现档位](execution.md) 的 `ultra` 无关。

只接受以上键及类型。缺文件、无效 JSON、空模型名、缺字段、未知键或超过两个升级阶段时，指出文件和错误，暂停依赖配置的分派；其余工作继续。不要静默使用旧的硬编码路由，不为修复配置错误擅自改用户文件。

## 生效范围与优先级

1. 宿主工具能力、权限和高优先级指令始终约束调用。
2. 用户当前明确指定的模型/角色/深度，按其指定范围覆盖配置；用户锁定某角色时不得用升级规则绕过。配置不能被用来推翻当前用户指令。
3. 未被用户覆盖的部分取自上述选中的配置文件。缺省分发配置继承宿主，不要求任何特定供应商。

主代理的模型由用户在宿主中选择，本文件只配置被委派的开发与审核角色。quick、仅设计/计划、只定位和单次 review 通常由当前代理执行，不为满足模型表强制创建代理。full 才按分工调度；独立性来自不同实例与上下文边界，同一模型也不能由同一实例自审。

开始 full 时记录本次实际采用的配置与宿主限制。任务中修改所选配置文件后，在下一次分派前重新读取，只影响后续角色，不替换正在运行的代理，不重置轮次和修复预算。变更后的阶段无法与旧账本对应时，由主代理明确剩余预算再继续。

配置解析成功后，委派能力、模型/深度可用性、访问授权及调用故障统一按 [setup.md](setup.md) 处理；本文件只决定请求的角色配置，不证明它已经实际生效。

## 升级

初始 developer/reviewer 为阶段 0，`upgrades[0]` 为阶段 1，`upgrades[1]` 为阶段 2。本文件只定义字段与编号；触发条件、预算与停止规则全部见 [orchestration.md](orchestration.md) 的"升级与停止"。
