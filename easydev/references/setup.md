# 环境与调用适配

仅在准备委派、核对能力或调用失败时读取。模型分配按 [models.md](models.md) 的路径优先级选择配置，这里不维护第二份模型表；配置读取失败按该规则暂停分派，不用继承默认值绕过。

先读取当前宿主暴露的工具说明：是否允许子代理、可用模型、深度参数、上下文隔离选项、写入权限和并发限制。使用真实工具接口，不硬编码旧的 `collaboration.spawn_agent`、参数名或插件版本路径；不通过 CLI 或另建用户会话规避宿主限制。

- 用户明确指定的模型、供应商和禁止委派约束优先。预设模型仅在工具允许覆盖、确实可用且已有对应授权时使用；skill 的文字不能扩大工具权限。
- 配置或用户指定的具体模型与深度是硬性要求：工具不允许按该值覆盖时暂停相关分派并报告受阻，不得改用继承模型，也不得只在说明后继续。只有选中配置为 `inherit`（或没有任何配置来源）时才使用工具规定的继承模型，并保持独立实例和只读审查。
- 若已开始使用的供应商因权限、额度、模型不存在或网络失败而不可用，先分类故障；不要静默换供应商、切配置或无意义重试。仅按用户已有授权使用替代，否则完成不依赖该调用的工作并说明阻塞。
- 跨供应商交接只给必要代码、需求和证据，不发送凭证或完整会话；不得自动修改 API key、默认模型、全局开关或连接设置。
- 没有子代理能力：可完成授权实现和自查，说明独立审查受阻；不能由同一实例切换口吻后声称独立审核。用户只要求 review/audit 时，按 [review.md](review.md) 的作者隔离规则执行；本会话产生的改动只能标为自查（非独立）。

配置模型不授予第三方访问权限，也不授权安装供应商或设置密钥。模型和推理深度都须核对工具支持范围；用户明确锁定的要求无法满足时报告受阻，不擅自替换。记录实际模型/深度：先取工具返回值，再查宿主允许访问的运行记录或事件；确无记录或不可访问时才注明未知及原因，不能把请求值当作运行证据。

选择不继承完整会话的选项时，以实际接口支持为准；不支持该选项就说明隔离限制，不伪称干净上下文。角色至少用不同实例分离，参与某次实现的实例不得审查自己写的结果。

创建子代理不等于创建新的用户聊天。仅在用户明确要求新聊天时使用聊天管理工具。

## Google Antigravity（AGY）

- 安装位置按 [官方 Skills 文档](https://antigravity.google/docs/skills)：项目级为 `.agents/skills/easydev/`；App/IDE 用户级为 `~/.gemini/config/skills/easydev/`，CLI 用户级为 `~/.gemini/antigravity-cli/skills/easydev/`。保持 `SKILL.md` 与 `references/` 等运行时文件的相对位置；安装步骤及 Skills CLI 目录映射见 [README](https://github.com/chenpey/easy_suite/blob/main/easydev/README.md#常见目录)。
- 先确认宿主已发现技能，App/CLI 可通过 `/easydev` 显式调用。目录存在或文档兼容不代表当前宿主已加载、激活或通过行为回归。
- 原生委派按 [官方 Subagents 文档](https://antigravity.google/docs/subagents)：使用当前工具实际暴露的 `invoke_subagent`；自定义代理的 `subagent` 必须允许调用。将开发/审查角色映射为独立实例，审查仅给必要材料与只读权限，不因工具同名假定各版本参数相同。
- 配置中的模型 ID、推理深度及工作区隔离选项须逐项核对宿主工具能力；不能把模型层级当成任意供应商 ID，或静默忽略不支持的设置。无法满足时沿用本文件的受阻规则，不虚称独立审查通过。
- Antigravity 同样按外部配置 > 对话指定 > 内置 `inherit` 的优先级读取，不附带专用模型示例。用户可按角色选择模型，位置在 Skill 安装目录外的 `easydev/models.json`；模型层级、推理深度及覆盖是否生效须以当前 `invoke_subagent` 工具接口和宿主指令为准，未回传时按运行记录或事件核对，确无可访问记录才标未知并说明原因。
