# 工作区隔离与分支收尾

仅在任务需要隔离、用户要求或长任务需要独立工作区时使用；局部小改动直接在当前工作区完成，不必建工作树。同一任务仍只有单一写入者。

## 创建隔离工作区

- 优先宿主原生工具（如 Codex 的工作树创建/归档工具）；已有原生工具时不手工执行 `git worktree add`，避免宿主看不到的幽灵状态。
- 无原生工具时回退 `git worktree add`；先确认已在隔离工作区或处于子模块（子模块不是 worktree），不重复创建。目标目录优先项目已有的 `.worktrees/` 约定，创建前确认其被 `.gitignore` 忽略。
- 基准按任务指定分支或宿主默认分支；不静默从 main/master 开始，除非用户明确同意。
- 创建失败（权限/沙箱）时不绕过限制，说明原因并在当前目录继续，同时记录基线。
- 新工作区先运行项目相关检查建立干净基线；失败时报告，不让脏基线污染后续结论。

## 收尾与集成

1. 先完整跑本任务的验证（测试、lint、构建按项目实际情况），绿了再进入集成；失败则报告并停止。
2. 检测当前是普通仓库、命名分支工作树还是外部管理的 detached HEAD，据此选择选项；确认要合入的基准分支，不硬编码 main/master。
3. 呈现并等待用户选择：本地合并 / 推送并创建 PR / 保留现状；detached HEAD 只有后两项。集成决定属于用户，不代为合并、推送或发布。
4. 合并后重跑验证；失败时停止，保留分支与工作树以便恢复。推送、创建 PR、发布按宿主规则与实际授权执行。
5. 清理仅针对本任务创建且已确认不再需要的部分：优先宿主原生清理工具，回退 `git worktree remove` + `prune`。删除被拒绝时列出未提交内容让用户选择，绝不擅自 `--force` 或丢弃分支。

## 边界

- 只记录本次隔离与集成状态，不复制凭证或无关文件；工作树与分支的删除属于不可逆操作，必须等用户明确选择。
- 无法使用隔离工作区时如实说明，仍按 [execution.md](execution.md) 的任务基线保护用户已有内容。
