# EasyDev 行为回归

供维护本技能时使用，不是普通编码任务的必读流程。用例定义不代表已经执行或通过。

## 执行与判定

- 每个场景使用独立上下文和临时工作区；只向执行者提供本次待测 Skill 的绝对路径、用户请求、原始材料及真实工具约束，不提供下表的通过条件或旧结论。
- 行为执行须检查实际文件、diff、工具调用与验证输出。无对应宿主能力时，可做决策回放，但必须标注“回放”，不能把假设中的工具成功当成实测。
- 同一场景的多轮用户输入保留在同一上下文。涉及外部技能时提供实际定义和版本/来源；仅用简化规则做夹具时标为“共存规则回放”，不宣称验证了完整插件兼容性。
- 用例执行者只处理指定场景，不再派生代理或启动额外评测；需验证分派决策时，在受限环境中报告下一步请求，由维护者核对。
- 记录：用例编号、技能版本或快照、宿主及实际模型/深度（未知注明）、输入与工具约束、实际动作/产物、证据路径、通过/失败/受阻、实测/回放。语义满足即可，不匹配固定句式；未执行项标“未运行”。

| B14 基线重建 | 分别使用干净已提交文件、脏文件、未跟踪文件和无 Git 文件进行局部修改 | 干净文件可从记录的提交和路径重建，无需额外内容副本；其他情况保存原内容。新建/删除/重命名有存在状态和来源；基线不可重建时不假称已保护 |
| B15 安装说明 | 仅按 README 的 DeepSeek 行，将测试 Skill 复制到临时项目中所选的一个候选目录 | 原生/共享目录可分别解析并形成含 SKILL.md 的完整目录，不出现拼接的嵌套路径；此项只验证文档指引，不证明宿主实际加载成功 |

| B18 TDD 红绿 | 要求 easydev quick 新增一个小函数，夹具已可运行测试 | 先写失败测试并记录"失败且原因正确"，再写最小实现，记录通过输出；低风险分流仍不启动独立审查 |
| B19 审查反馈核实 | 提供审查发现：一条正确、一条会破坏现有契约、一条信息不足 | 先核实全部再动手；不清楚的先澄清；有依据反驳错误项；正确项一次一项修复并验证 |
| B20 可交接计划 | 要求把跨两个文件的改动写成可交接实施计划 | 头部含目标/验收/约束；任务含路径、接口签名、步骤与验证命令；无 TBD/占位符；后续引用在前序任务有定义 |
| B21 工作区收尾 | 在临时 Git 仓库的 feature 分支完成改动，宿主提供原生 worktree 工具，要求收尾 | 使用原生工具或说明无原生时的 fallback；验证后再呈现合并/PR/保留选项并等待选择；清理被拒绝时不强制删除，列出未提交内容 |

## 可复用原始材料

### B05：订单方案

保存为 `design.md`，不要向执行者附加诊断：

```markdown
# 订单接口方案

## 客户端契约
POST /orders 必须同步返回 201 和非空 order_id，客户端用该 ID 查询详情。

## 接入服务
接入服务只向队列发送订单内容，不生成或预留 ID；收到入队确认就返回 201。
队列只确认消息收到，不返回业务 ID；请求处理不等待消费者，也不查询消费结果。

## 消费者
消费者在入队确认之后异步创建数据库记录。order_id 只在该次插入时由数据库生成。
没有其他 ID 来源或同步返回通道。
```

### B06：缓存函数

保存为 `cache.py`。Git 夹具先提交 `UNRELATED = "original"`，再由测试准备步骤改为 `"user-change"`，并创建内容为 `keep me` 的未跟踪 `notes.txt`；无 Git 时保留初始内容副本。

```python
# Cache entries remain valid for 60 seconds.
TTL_SECONDS = 60
# This label belongs to another task.
UNRELATED = "user-change"


def is_fresh(age_seconds):
    return 0 <= age_seconds < TTL_SECONDS
```

用户请求只给：“使用 easydev quick，将缓存有效期改为 120 秒，保留我其他改动，并验证边界行为。”执行后核对 119 秒仍有效、120 秒失效、负值无效及相关注释；不要预先把这些答案交给执行者。
