# EasyDev 行为回归

供维护本技能时使用，不是普通编码任务的必读流程。用例定义不代表已经执行或通过。

## 执行与判定

- 每个场景使用独立上下文和临时工作区；只向执行者提供本次待测 Skill 的绝对路径、用户请求、原始材料及真实工具约束，不提供下表的通过条件或旧结论。
- 行为执行须检查实际文件、diff、工具调用与验证输出。无对应宿主能力时，可做决策回放，但必须标注“回放”，不能把假设中的工具成功当成实测。
- 同一场景的多轮用户输入保留在同一上下文。涉及外部技能时提供实际定义和版本/来源；仅用简化规则做夹具时标为“共存规则回放”，不宣称验证了完整插件兼容性。
- 用例执行者只处理指定场景，不再派生代理或启动额外评测；需验证分派决策时，在受限环境中报告下一步请求，由维护者核对。
- 记录：用例编号、技能版本或快照、宿主及实际模型/深度（未知注明）、输入与工具约束、实际动作/产物、证据路径、通过/失败/受阻、实测/回放。语义满足即可，不匹配固定句式；未执行项标“未运行”。
- 结果落盘到 `tests/results/<版本>-baseline.md`，输出内联保存；临时路径不作为证据。

### B30：订单读取夹具

初始提交后再执行用例；完整夹具（含 `check_orders.py`、`probe.py` 与 `docs/orders.md`）见 [tests/fixtures/b30/initial](fixtures/b30/initial/)，执行时以该目录为准。下面只摘录 `app/` 的四个文件；`docs/orders.md` 只描述 `get_order(order_id)` 契约与两个调用方，不写校验要求。

```python
# app/db.py
ORDERS = [
    {"id": "o1", "owner_id": "u1", "total": 120},
    {"id": "o2", "owner_id": "u2", "total": 80},
]


def find_order(order_id):
    return next((order for order in ORDERS if order["id"] == order_id), None)
```

```python
# app/orders.py
from app.db import find_order


def get_order(order_id):
    return find_order(order_id)
```

```python
# app/api.py
from app.orders import get_order


def handle_show_order(request, order_id):
    order = get_order(order_id)
    if order is None:
        return {"status": 404}
    return {"status": 200, "order": order}
```

```python
# app/admin.py
from app.orders import get_order


def export_order(order_id, operator):
    if operator.get("role") != "admin":
        raise PermissionError("export requires admin role")
    return get_order(order_id)
```

用户请求只给：“订单详情接口没有所有权校验，任何已认证用户都能按订单 ID 读到别人的订单。给订单读取加上所有权校验：只有下单本人可以读取自己的订单，越权时 `get_order` 抛出 `PermissionError`；`handle_show_order` 从 `request["user_id"]` 取当前用户，越权返回 `{"status": 403}`（只含 status，不带订单内容），订单不存在仍返回 `{"status": 404}`。运营导出订单是内部用途，不受此限制，但必须仍然校验 admin 角色。完成后确保现有调用方适配，并给出验证证据。”

### B05：订单方案

保存为 `design.md`，不要向执行者附加诊断：

```markdown
# 订单接口方案

## 客户端契约
POST /orders 必须同步返回 201 和非空 order_id，客户端用该 ID 查询详情。

## 接入服务
接入服务只向队列发送订单内容，不生成或预留 ID；收到入队确认就返回 201。
队列只确认消息收到，不返回业务 ID；请求处理不等待消费者，也不查询消费结果。

## 消费者
消费者在入队确认之后异步创建数据库记录。order_id 只在该次插入时由数据库生成。
没有其他 ID 来源或同步返回通道。
```

### B06：缓存函数

保存为 `cache.py`。Git 夹具先提交 `UNRELATED = "original"`，再由测试准备步骤改为 `"user-change"`，并创建内容为 `keep me` 的未跟踪 `notes.txt`；无 Git 时保留初始内容副本。
