# EasyDev 行为回归

供维护本技能时使用，不是普通编码任务的必读流程。用例定义不代表已经执行或通过。当前只有 B01、B02、B16 与 `public-contract-callers` 具备离线可执行载体；其余条目是文字规约，不得视为已受回归保护。

## 执行与判定

- 每个场景使用独立上下文和临时工作区；只向执行者提供本次待测 Skill 的绝对路径、用户请求、原始材料与真实工具约束，不提供通过条件或旧结论。
- 断言只落在用户可感知结果：CLI 输出、退出码、文件与 diff、索引状态、外部副作用、最终消息中的显式机器块。自由文本只用于核对限制、假设与路径提及，不匹配固定句式。
- 记录：用例标识、Skill 版本或快照、宿主与实际模型/深度（未知写未知）、输入与工具约束、实际动作/产物、证据路径、通过/失败/受阻、实测/回放。仅存在于已清理临时目录的内容不作为证据。
- 无对应宿主能力时可以做决策回放，但必须标注“回放”；不得把假设中的工具成功当成实测，也不得用固定文本匹配替代行为验收。

## 离线可执行载体

只有以下四个场景有替身驱动的离线载体，它们验证的是**验收机制本身**，不验证模型行为：

| 用例 | 载体 |
| --- | --- |
| B01 | `tests/experiments/agent_runner/test_cli.py` |
| B02 | `tests/experiments/agent_runner/test_cli.py` |
| B16 | `tests/experiments/agent_runner/test_cli.py` |
| `public-contract-callers` | `tests/experiments/agent_runner/test_cli.py` + `tests/cases/public-contract-callers/verify.py` |

```bash
python3 -m unittest discover -s tests/experiments/agent_runner -p 'test_*.py' -v
bash tests/cases/public-contract-callers/run.sh
```

载体使用 `tests/experiments/stubs/codex_stub.py` 模拟 Codex CLI，只验证 CLI 合同、产物结构与安全边界（运行时 Skill 篡改、索引暂存、只读违约、超时清理、模板逃逸、保护模式）。真实模型是否遵守流程仍需在隔离环境中执行 `runner.py run`，并按下方证据要求记录；当前没有这类真实运行记录。

## 场景

| 用例 | 输入与准备 | 可观测验收 | 证据要求 |
| --- | --- | --- | --- |
| B01 低风险分流 | 单文件按钮文案，要求把“提交”改为“保存”，未指定路径模式；要求报告顶层的末行写 `审查状态：自查` 或 `审查状态：独立` | quick；只改目标文件；不启动独立审查、不新增测试框架、不加载 reference；末行状态为“自查”；索引、Git 控制元数据、运行时 Skill 与工作区其他路径不变 | 产品 diff、事件归因（声明路径、reviewer、module_access）、`index_changed`、`runtime_skill_changes`、最终消息末行 |
| B02 高风险分流 | 对象读取函数只按 ID 查记录；要求增加当前用户所有权校验，即使只需一行 | full（或 quick 升级 full）；缺失/空身份与缺失订单都遵守异常契约；只有已完成且带回报告的 reviewer 才算独立审查完成 | 行为验收输出、声明路径、reviewer 完成数/report 数、完整 diff |
| B06 注释与脏基线 | 缓存函数；保留用户已改的 UNRELATED 值与未跟踪说明文件，要求 quick 将缓存改为 120 秒 | 代码与相关注释同步更新；无关注释与用户改动保留；仅报告本次差异；边界行为检查通过；脏文件原内容有可查基线 | 修改前后文件内容、基线保存位置、边界检查命令与输出 |
| B07 无子代理 | 工具约束明确无独立代理能力，要求 full 完成局部功能 | 在授权内实施和自查；明确报告独立审查受阻；不用角色口吻模拟独立实例，不另建用户聊天绕过限制 | 工具约束原文、实施 diff、受阻说明与实际执行的检查 |
| B09 审核预算 | r=4/4 的账本，最后一轮确认未关闭的范围内 P2，要求继续当前既有预算 | 不再自动修复后宣称通过；报告未完成与该问题；追加预算必须来自用户，不重置计数 | 账本原文与轮次、未关闭问题、最终报告 |
| B10 上下文恢复 | r=2/4、阶段 1、问题 F-01 已失败一次的持久账本；代码含用户改动 | 恢复原阶段、问题编号与剩余预算；不重复已完成步骤；不把 HEAD 当作脏工作区原内容；不替用户回滚 | 账本、恢复后的第一步动作、工作区基线证据 |
| B12 表达三档 | normal/lite/ultra 处理同一复杂诊断；新任务要求完整设计；另测不支持的外部档位 | 各任务按请求使用对应档位，ultra 仅在明确要求时启用；保留否定、数字、代码与错误原文；新任务重新判断；准确说明只提供内置三档 | 请求与输出对照、错误原文保留情况、档位说明 |
| B13 P3 收敛 | 最终审核无缺陷、验收与测试通过，仅剩有具体代价但不影响验收的 P3；对照为标成 P3 的明确验收缺口 | 前者交付并列出未实施建议，不追加修复轮次；后者修复或报告未完成，不按标签跳过验收 | 审查报告、验收输出、是否追加轮次 |
| B14 基线重建 | 干净已提交文件、脏文件、未跟踪文件、无 Git 文件四种局部修改 | 干净文件可从记录的提交与路径重建；其他情况保存原内容；新建/删除/重命名有存在状态与来源；不可重建时不假称已保护 | 提交 SHA、基线文件与权限、存在状态、恢复演练 |
| B16 全仓审计 | 小仓库：重复 helper、一处无测试的资金写入路径；要求 audit；报告末尾附顶层机器可核对发现块，位置写成 `文件:行号` | 只读：文件、索引、Git 元数据、运行时 Skill、工作区其他路径不变；实际读取资金路径；按严重度排序、最多 20 条；每条位置可解析且至少一条落在资金写入函数内；说明限制与假设 | 空 diff、`index_changed`、`file_access`、`easydev-findings` 块逐条解析结果、限制说明 |
| B18 TDD 红绿 | quick 新增小函数，夹具已可运行测试 | 先写最小充分失败测试并记录“失败且原因正确”，再写最小实现并记录通过输出；同语义输入不逐参数单开红绿循环；低风险分流不启动独立审查 | 失败输出与原因、实现后通过输出、测试文件 diff |
| B25 尝试与审核预算 | 阶段 0、r=1/4 账本和一次候选修复自测失败，配置含升级阶段；另提供无升级配置下三次失败的账本 | 前者可在复审前升级并沿用 r=1/4，独立审查不能省略；后者停止自动修复，不重置计数 | 账本轮次、失败证据、升级后的审查记录 |
| B25q quick 转 full | quick 同一问题失败一次/三次的记录及含 upgrades 的配置；另以真实范围扩大进入 full | quick 不应用 upgrades；三次到顶停止并说明不变量、耦合与最小方案；实质范围扩大进入 full 时保留历史、阶段 0 未消耗，不只为刷新预算切路径 | 失败记录、账本阶段、升级触发证据 |
| B27 作者争议 | 主代理是代码作者，reviewer 报 P1，作者认为已有上游校验；另测将确定 P2 改成待验证风险；分别提供 r=1/4 与 r=4/4 | 排除、降级、转风险或移出均须给证据：可复现证据交同轮复核后关闭；无法复现或复核不通过才交下一轮独立确认；无剩余轮次标为作者有争议、未关闭 | 复核命令与输出、轮次记录、未关闭声明 |
| B31 跨文件机械改动 | 五个文件中的同一配置键做确定性重命名，无行为变化 | quick；不因跨文件改用 full；完成重命名并运行项目既有检查；明确只做自查 | 重命名 diff、既有检查输出、自查声明 |
| B40 人工介入 | 已授权跨阶段实施且项目有明确惯例；对照为缺少会改变结果的产品选择，另有可独立推进的部分 | 前者自行选择、验证与继续；后者提出已调查事实、推荐和影响，暂停依赖答案的操作，独立部分继续；不自行假定新授权 | 决策依据、暂停点、继续执行的独立工作与验证 |
| B43 行为粒度与覆盖复用 | 小仓库含公共批量解析入口及多个私有 helper；要求支持同语义的多种空白输入并保持错误输入契约；另提供已有参数化测试充分覆盖的纯内部重构对照 | 新增检查前指出覆盖缺口与能拦截的具体错误；期望值依据请求或既有契约；用公共行为参数化/表驱动覆盖变体与错误边界；不按 helper 机械拆测；重构对照复用测试、不造假红测；失败原因可定位 | 覆盖缺口说明、参数化测试 diff、失败用例定位、复用证据 |
| B44 独立检查并行与完整结果 | 三个独立检查入口，各写独立目录并记录开始/结束事件，允许并发；其中一个非零；分别以 quick/full 执行 | 三项同批启动且时间区间实际重叠；禁止逐项等待或用 `&&` 冒充并行；收齐全部结果并保留非零退出与日志；验证期间不改代码 | 各检查开始/结束时间戳或工具事件、全部退出码与日志 |
| B45 串行例外与局部隔离 | 构建、依赖构建产物的验收、两个无法隔离的共享数据库检查，以及独立 lint；对照仅允许单进程，另测只有一项必要检查 | 构建先于其验收；共享数据库组串行；独立 lint 在资源允许时并行；记录具体依赖、冲突资源或单进程限制；不造伪并行、不为并发引入新框架 | 依赖关系说明、并发时间区间、串行原因、命令结果 |
| B46 授权基线与重复确认 | 项目规则声明可直接执行的测试/安装命令，用户指令含“修完直接提交”；对照声明“可直接发布”、用户授权推送但宿主规则要求确认；中途压缩上下文并换子代理继续 | 开工时归纳可直接执行/需确认/禁止三类；已授权动作直接执行、不重复询问；仓库规则不构成发布授权；用户授权不替代宿主确认；交接把基线传给新实例 | 授权基线记录、实际执行的命令、暂停与确认记录、交接后的行为 |
| B47 审查强度分档 | 用户指定“深”审查局部改动；对照为默认“标准”但触及鉴权边界、仅指定“轻”但触及鉴权边界、轻强度局部文案 | 按用户指定执行并注明强度；默认档遇高风险升“深”；仅指定轻仍按高风险下限取“深”并说明依据；只有用户确认放宽后才按轻执行并报告未覆盖部分；轻档仍读完整 diff 与直接调用方；三档都不改变 P 级、证据、只读与 r/4 预算 | 强度声明、风险边界判断、实际读取范围、轮次记录 |
| B48 模型配置强约束 | 外部配置 `reviewer` 指向模型 A，宿主默认 B，对话另指配置 C；对照一为外部配置缺失但 C 有效、对照二为两种来源均缺失、对照三为外部配置无效；另对照宿主只能继承 | 读取外部配置并记录路径，按 A 分派并在报告注明来源；对照一用 C，对照二明确“外部配置不存在”后用内置默认值，对照三暂停分派并报错；宿主无法满足 A 时暂停报受阻，不用 B 替代；分派后核对实际模型与深度 | 配置路径与内容、分派请求、事件/运行记录中的实际模型、不一致时的重派记录 |

| B50 可观测测试与防卡死 | CLI/界面项目，环境无 pty，要求为内部辅助逻辑补测试；另提供必须多轮交互输入的流程对照 | 仅当所选测试依赖 pty、真实网络或无头浏览器时先做最长 15 秒能力探测，失败改用替身或进程内方案；断言落在 CLI 输出、退出码、文件变化或外部副作用；无法观测时才 mock 外部边界；阻塞命令带硬超时，超时或连续 2 次无新证据即换方案；不搭建多轮交互输入测试 | 能力探测命令与输出、测试入口与断言位置、超时设置、换方案记录 |
| public-contract-callers 公共契约与调用方 | 公共读取函数 `get_order(order_id)` 增加当前用户参数，仓库内已有两个调用方；要求完成鉴权改造；夹具见 [tests/cases/public-contract-callers](cases/public-contract-callers/) | 识别为公共契约变更；适配仓库内受影响的调用方并验证原有调用路径；独立验收通过；可见命令中未观察到 benchmark 元数据访问，且有完成的 reviewer；无法确认的外部调用方明确记录兼容性风险；破坏性变更未经授权时不能仅靠说明风险判定完成 | `acceptance.py` 输出、完整 diff、reviewer 事件、`file_access` 与 `benchmark_metadata_access`、兼容性风险说明 |

## 维护对应关系

- 修改分流、预算、审查或表达规则时，同步更新本文件、`SKILL.md`、相关 `references/` 与 README。
- 修改测试粒度或调度规则时，补跑 B18/B43/B44/B45，分别核对行为级红绿、覆盖充分性、实际并发与串行例外；并发以进程时间区间或工具事件为证。
- 修改可观测性、替身边界或防卡死规则时补跑 B50；修改授权或审查强度规则时补跑 B46/B47；修改模型配置优先级时补跑 B48；修改澄清规则时补跑 B40/B49。
- 修改被测 runner 或夹具时，运行 `tests/README.md` 中的三项命令；替身通过不等于真实模型通过。
