# EasyTest 0.3.0 迁移与整改记录

适用版本：0.3.0；日期：2026-09-28。整改依据为
[0.2.0 全面代码与体验评审](../review-2026-09-28.md)，该报告保留原始评审基线。
本版优先处理响应读取、敏感配置、编辑预检、Excel 诊断和失败控制。
真实业务及独立 AI 接入验收仍待开展，框架回归结果不能替代生产验收。

## 1. 本版范围

| 评审事项 | 本版结果 | 边界 |
| --- | --- | --- |
| P0 HTTP 大响应 | 内置 HTTP 流式读取、响应字节上限、哈希及超限失败元数据 | 限制解压后的响应体，不提供文件下载 artifact API；不限制 Mock、第三方 handler 或 Python 解码后的对象内存 |
| P0 敏感信息约束 | 敏感 HTTP header 来源校验，项目 secret/PII 键，URL 清洗 | 动态引用不能证明其上游来源可信；不保证识别任意业务字段 |
| P0 真实业务与独立 AI 试点 | 保留验收模板 | 没有业务环境、账号或独立试点结果，不标记完成 |
| P1 编辑闭环 | `edit --validate` 在替换前使用项目配置与策略预检 | 预检当前工作簿中启用的 Case；跨文件整体检查仍需 `validate cases` |
| P1 Excel 定位 | Case 行号、sheet、column、原始/期望类型补充到错误；文本列拒绝隐式转换 | 不自动修复 ID 或业务数据；没有来源坐标的错误不伪造坐标 |
| P1 CLI 失败控制 | `--fail-fast`、`--max-failures N`、后续 Case 标为 `not_run` | 在 Case 边界停止，不回滚已发生的写操作 |
| 发布验证 | Python 3.12/3.13 工作流、编译一致性门禁、独立 wheel 验证脚本 | 本地双版本验证与远端 CI 状态分别记录 |

声明式轮询、Schema、OpenAPI 导入、xdist 聚合、共享鉴权、数据库连接复用与大表
优化继续按原报告分阶段推进。本版不引入跨 Case 全局可变状态，同一个 Runner
仍不应跨线程共享。

## 2. 升级步骤及兼容变化

版本号由 0.2.0 升至 0.3.0。公共命令和默认继续执行行为保持兼容，但以下严格校验
可能让旧配置提前失败。安装后先检查当前契约，再编译、预检并运行离线回归：

```bash
python -c "import easytest; print(easytest.__version__)"
python -c "from importlib.resources import files; print(files('easytest').joinpath('CONTRACT.md').read_text())"
easytest compile cases
easytest compile cases --check
easytest validate cases --root . --profile offline-strict
easytest run cases --root . --profile offline-strict --result artifacts/result.json
```

重新编译是必要步骤：编译产物中的 `compiler_version` 变为 `0.3.0`。
请将 XLSX 和生成的 JSON 一起提交，仍只编辑 XLSX。JSON-only 项目继续显式使用
`source_mode: "json"`，不伪造编译元数据。

### HTTP 响应上限

可在 `config/runtime.json` 中合并以下配置：

```json
{
  "http": {"max_response_bytes": 10485760},
  "redaction": {
    "secret_keys": ["access_code"],
    "pii_keys": ["customer_code"]
  }
}
```

默认 10 MiB，允许范围为 `1..67108864` 字节（硬上限 64 MiB），必须是整数。
operation 的 `max_response_bytes` 只能小于或等于项目上限；Step request 只能进一步
收紧 operation 上限。动态 Step 值在执行时再次检查；直接使用 `HttpExecutor`
同样不能抬高 operation 上限。

`stream: true/false` 都使用受限读取。重定向中间响应和 gzip 解压后的响应体也受限。
正常返回增加 `response_bytes/sha256/hash_scope/truncated` 元数据。
超限抛出 `HTTP_RESPONSE_TOO_LARGE`，报告保留状态码、脱敏 headers/URL、
`observed_bytes/max_response_bytes/sha256/hash_scope="observed_prefix"` 和截断原因，
`body` 为 `null`。已观察前缀最多为上限加 1 字节，哈希不代表完整响应。

超限关闭响应，不自动重试，不执行该步骤的断言或快照，后续步骤不执行。
CLI、pytest 使用的 Runner 和 Notebook 共用此行为。`HttpClient` 返回给调用者的
原始结果/异常元数据属于业务数据，自动脱敏适用于框架报告和事件。
需要大文件下载时使用经过业务审核的 adapter 管理 artifact 和清理，不盲目提高上限。

### 敏感 header 与脱敏

operation 中的 `Authorization`、`Proxy-Authorization`、`Cookie`、API key 及包含
token/secret/password 的 header 不再接受明文值，使用环境变量引用：

```json
{
  "headers": {
    "Authorization": "Bearer ${HTTP_TOKEN}",
    "Cookie": "${HTTP_COOKIE}"
  }
}
```

支持纯 `${ENV_NAME}`，以及 `Bearer ${ENV_NAME}` / `Basic ${ENV_NAME}` 格式。
Step request 与 inject Mock 使用 `${variables.*}`、`${steps.*}`、`${state.*}`
动态引用；这只是来源形式检查，上游 variables 或 handler 仍需业务方管理凭据。
整个 headers 对象的动态引用也不能证明内容可信。缺少真实凭据的离线 Mock
预检无需解析未使用的 operation 环境变量；真实请求仍需要凭据。

项目扩展键作用于嵌套报告值、断言差异和事件，作用域在 Case 结束/失败后恢复。
URL 清洗处理 userinfo、敏感 query（含编码后的键名）及 fragment。
任意路径或未知业务字段可能仍含敏感信息；快照原始基线、Notebook 原始交互输出、
业务 handler 自行输出及外部日志不属于本机制的自动保护范围。

### 原子编辑与 Excel 类型

```bash
easytest edit cases/demo.xlsx --patch edit.json --validate --root . --profile offline-strict
easytest validate cases --root . --profile offline-strict
```

先在临时工作簿应用补丁，检查契约，再按项目配置/执行策略预检工作簿启用的 Case，
最后替换 XLSX 并重新编译。预检失败保留原 XLSX/JSON，清理临时文件。
预检不执行 handler 或业务请求。`--profile/--execution-policy` 需要 `--validate`。
不加 `--validate` 仍仅做工作簿契约检查。
XLSX 和 JSON 不是文件系统多文件事务；编译产物写入失败后应重新执行 `compile`。

ID、名称、operation、tags 等文本列如果被 Excel 保存为数字、日期或布尔值，
现在会明确失败。先核对业务原值，再由维护者将单元格保存为文本；框架不会补前导零
或自动转换数据。错误 JSON 新增可用的 `sheet/column/actual_type/expected_type`，
原有 `source/source_row` 仍保留。

### CLI 失败控制

```bash
easytest run cases --root . --profile live --fail-fast --result artifacts/result.json
easytest run cases --root . --profile live --max-failures 3
```

上述两个参数互斥，`N` 必须为正整数，默认不限制失败数。整批预检始终先于第一条
业务执行；运行达到失败数后剩余 Case/Step 为 `not_run`，整体状态为 `failed`。
中断仍为 `interrupted`，没有开始的项不计入 passed。
这两个参数仅属于 CLI；pytest 使用 `-x/--maxfail`，Notebook 由调用代码控制下一次
调用。失败阈值不是事务回滚：清理仍放在业务 `finally` 或 fixture。

## 3. 回归范围与验证结果

测试范围为 HTTP transport/executor/config/preflight、项目脱敏、编辑预检、Excel
编译诊断和 CLI 失败控制。新增 61 个参数化回归场景，旧 HTTP 替身适配流式读取；
未放宽原断言。

缺陷分析：除了原评审项，本轮补测发现直接调用 `HttpExecutor`、operation 不含
`executor` 字段时请求可抬高上限；已统一入口检查并验证请求发送前失败。
另外将动态响应上限留待运行时检查，避免静态预检误拒绝合法步骤引用。
相关测试见 [test_http_limits.py](../tests/test_http_limits.py)，修复位于
[HTTP executor](../src/easytest/executors/http.py)。旧测试替身缺失
`iter_content` 或缓存消费状态造成的兼容失败已修正为真实 Response 语义。

新增用例覆盖：

- 上限边界、gzip、重定向、stream、无效配置、读取异常/中断与响应关闭。
- CLI/Runner/Notebook 超限报告、不执行断言快照、后续步骤 `not_run`。
- 敏感 header 字面量、离线环境引用、项目脱敏键、URL 和作用域恢复。
- 编辑成功、项目预检失败、策略文件缺失、临时保存失败/中断与原文件保留。
- Excel Case 行定位、数字/日期文本、非法 Case 类型、非法 enabled/variables 和前导零保留。
- 默认继续、首次失败停止、失败数阈值、无效参数及 stdout/result 一致。
