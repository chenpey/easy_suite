# EasyTest 0.3.1 快照存储优化记录

## 设计前提

0.3.1 面向尚未部署、没有历史运行数据的新项目。实现只保留当前契约，不提供旧
SQLite schema、旧快照 codec、内嵌截图、旧参数或旧公共 API 的迁移与兼容路径。
遇到非当前格式时直接失败，由使用者删除并重新生成数据。

## 快照存储

- SQLite schema 固定为 `user_version=1`，表和列必须与当前定义精确一致。
- 响应和数据库快照使用带 magic header 的 raw 或 zlib level 6 编码。
- 截图使用 SHA-256 内容寻址，文件保存在
  `runtime.snapshot_artifact_dir`，SQLite 只保存相对路径、大小和哈希。
- `runtime.snapshot_max_bytes` 默认 256 MiB，最大 1 GiB，约束文件读取、
  SQLite BLOB 读取、解压结果和截图 artifact。
- codec 只接受 BLOB/`bytes`；无标记、TEXT、尾随数据、超限内容和损坏引用直接失败。

## 并发与维护

- SQLite 启用 WAL、`busy_timeout`、外部文件锁和 `BEGIN IMMEDIATE`。
- Case 开始时记录最新完成基线代次，结束时做乐观并发检查；同一 Case 的并发更新
  冲突返回 `SNAPSHOT_CONFLICT`，不静默覆盖。
- 运行级 lease 防止维护任务删除仍活跃的 `running` 记录。
- lock 文件保持稳定 inode，避免跨进程删除重建造成锁分裂。
- 预检在共享写锁下执行 immutable 读取；锁忙或 WAL 非空时推迟到运行期校验，
  同时保持预检不创建 SQLite sidecar 文件。
- artifact 清理不跟随符号链接，只处理合法的两级内容寻址文件。

维护命令：

```bash
easytest snapshot check --root .
easytest snapshot maintain --root .
easytest snapshot maintain --root . --stale-after-hours 24 --keep-failed 1 --compact
```

`maintain` 可清理已失活运行、超额失败/冲突记录、超额成功历史和孤立图片，并执行
WAL checkpoint、`PRAGMA optimize`；`--compact` 额外执行 `VACUUM`。

## 严格契约清理

本版本同时删除了与快照无关的历史兼容入口：

- `--case-json`、`.env`/环境变量 `RUN_MODE`。
- 缺少 `source_mode` 的旧编译 JSON 和缺少 `report_id` 的旧报告。
- 数据库裸参数对象、由 `run_mode` 推断数据库写权限。
- HTTP retry 整数简写及字符串数字的隐式转换。
- 快照 `sort_lists_by` 和 normalizer `paths` 别名。
- `send_http`、`DictObject`、`dict_to_obj`、`obj_to_dict`、
  `discover_cases`、`get_cookie_value` 等包装 API。

数据库 request 只接受空对象或 `{"parameters": ...}`；数据库写入必须显式设置
`allow_db_write=true`。快照列表排序统一使用 `unordered_lists`，normalizer 每条规则
只接受单个 `path`。
