# 新业务接入指南

适用版本：EasyTest `0.4.2`。

本指南面向首次接入 EasyTest 的业务测试人员。完整字段与错误契约见安装包内 `easytest/CONTRACT.md`，AI 协作见 [AI 接入与执行指南](AI接入与执行指南.md)，快速体验可先运行 [JSONPlaceholder Demo](../examples/jsonplaceholder/README.md)。

## 1. 准备环境

- Python 3.12 或 3.13，以及 [uv](https://docs.astral.sh/uv/getting-started/installation/)。
- 测试环境地址、认证方式、可用测试数据与预期结果。

| 角色 | 主要职责 |
| --- | --- |
| 业务负责人 | 确认测试环境、权限、业务预期与数据回收 |
| 用例维护人员 | 编辑 XLSX、执行测试、分析报告 |
| 框架维护人员 | 维护 EasyTest 核心、契约与版本 |

## 2. 创建独立业务测试项目

```bash
uv sync --python 3.12 --no-dev
uv run easytest init ../my-tests
uv run easytest run --root ../my-tests
```

生成目录包含 `cases/demo.xlsx`、`cases/demo.json`、`config/`、`test_cases.py`、`pytest.ini`、`AI_GUIDE.md`、`README.md` 与 `.gitignore`（默认使用离线 Mock）。

安装到独立虚拟环境：

```bash
cd ../my-tests
uv venv --python 3.12
uv pip install ../easytest
source .venv/bin/activate      # Windows PowerShell: .\.venv\Scripts\Activate.ps1
easytest run
```

### 2.1 在编辑器中选择正确解释器

在 `easytest/` 或独立业务项目创建 `.venv` 后，在编辑器中选择对应 `.venv`：

| 编辑器 | 选择方式 |
| --- | --- |
| TRAE CN / VS Code / Cursor | 状态栏点击 Python 版本，或 `Cmd/Ctrl+Shift+P` 执行 `Python: Select Interpreter` |
| PyCharm | `Settings/Preferences > Project > Python Interpreter > Add Local Interpreter > Existing` |
| Jupyter / VS Code Notebook | 点击右上角 `Select Kernel`，选择对应 `.venv` |

常见解释器路径：`${workspaceFolder}/.venv/bin/python`（仓库根打开时为 `${workspaceFolder}/easytest/.venv/bin/python`；Windows 为 `.venv\Scripts\python.exe`）。在集成终端执行以下命令确认：

```bash
python -c "import sys, easytest; print(sys.executable); print(easytest.__version__)"
```

## 3. 接入真实 HTTP 接口

### 3.1 环境配置

创建可提交的 `.env.example` 并复制为本地 `.env`（Git 忽略）填写真实测试凭据：

```dotenv
BASE_URL=https://test-api.example.invalid
HTTP_TOKEN=replace_with_your_test_token
```

### 3.2 定义接口

在 `config/operations.json` 配置 operation：

```json
{
  "operations": {
    "http.get_user": {
      "executor": "http",
      "method": "GET",
      "url": "${BASE_URL}/users/{user_id}",
      "headers": {"Authorization": "Bearer ${HTTP_TOKEN}"},
      "timeout": 10,
      "expected_status": [200]
    }
  }
}
```

### 3.3 编辑 Excel

`cases` 页：

| case_id | case_name | case_type | enabled | variables |
| --- | --- | --- | --- | --- |
| user.get | 查询已有用户 | http | true | `{"user_id":1001}` |

`steps` 页：

| case_id | step_id | order | executor | operation | request | expect |
| --- | --- | --- | --- | --- | --- | --- |
| user.get | get_user | 1 | http | http.get_user | `{"path":{"user_id":"${variables.user_id}"}}` | `{"$.status_code":200,"$.body.data.id":"${variables.user_id}"}` |

AI 或脚本可使用结构化补丁同步更新 XLSX 与同名 JSON：

```bash
easytest edit cases/demo.xlsx --patch edit.json --validate --root . --profile live
```

### 3.4 预检与执行

```bash
easytest validate cases/demo.xlsx --case-id user.get --profile live
easytest run cases/demo.xlsx --case-id user.get --profile live --fail-fast
```

## 4. 请求、断言与模板

常用请求：`{"path":{"user_id":1001}}`、`{"params":{"page":1}}`、`{"json":{"name":"测试用户"}}`、`{"data":{"name":"测试用户"}}`。

断言支持路径映射与 `checks`（`equals`、`contains`、`in`）：

```json
{"$.status_code": 200, "$.body.code": "SUCCESS"}
```

```json
{"checks": [
  {"path": "$.body.data.status", "in": ["ACTIVE", "PENDING"]},
  {"path": "$.body.data.name", "contains": "张"}
]}
```

模板变量：`${variables.user_id}`（Case 变量）、`${data.username}`（数据行字段）、`${steps.created.body.data.id}`（前序步骤输出）、`${state.user.id}`（Case 状态）、`${generate.uuid}`（Case 内稳定生成值）。

## 5. 数据驱动（共享数据集）

在 `cases` 页填写 `data_set`（如 `login_cases`），并在 `data` 页维护多组输入：

| data_set | data_id | enabled | username | password | expected_status |
| --- | --- | --- | --- | --- | --- |
| login_cases | valid | true | alice | correct | 200 |
| login_cases | wrong_password | true | alice | wrong | 401 |

步骤和断言通过 `${data.username}`、`${data.expected_status}` 引用当前行（完整占位符保留数字、布尔与空值类型）。运行全量或单行：

```bash
easytest run cases/login.xlsx --case-id login.case
easytest run cases/login.xlsx --case-id login.case.wrong_password
```

## 6. 报告与结果检查

默认生成 `artifacts/report.html`；需要 PDF 时增加 `--pdf-report artifacts/report.pdf`；机器读取使用 `--result artifacts/result.json`。建议按以下顺序排查：核对总数与状态 → 定位失败 Case ID 与 Excel 行号 → 查看失败阶段（`preflight/prepare/execute/assertion/snapshot`）→ 核对差异。

## 7. 业务流程编排与清理

通过 `save_as` 在同一 Case 内串联步骤（如 `save_as=created` 后引用 `${steps.created.body.data.id}`）。

### 数据清理示例

使用 pytest fixture 的 `try/finally` 确保测试资源稳定回收：

```python
import pytest

@pytest.fixture
def created_user(business_sdk):
    user = business_sdk.create_user(name="easytest temporary user")
    try:
        yield user
    finally:
        business_sdk.delete_user(user["id"])
```

## 8. 切换环境、Mock 与快照

- **环境预设**：`offline-strict`（离线 Mock）、`live`（真实执行）；受信任自动化环境通过 `EASYTEST_EXECUTION_POLICY` 限定执行范围。
- **离线 Mock**：在 `config/mock_profiles.json` 按 operation 配置模拟输出（优先级：Step > Case Mock Profile > 运行 Profile）。
- **快照对比**：在 `config/snapshots.json` 配置规则，步骤中设置 `{"rule":"user_detail","name":"user_detail"}`：

```bash
easytest run cases/demo.xlsx --case-id user.get --profile live --run-mode write    # 创建缺失基线
easytest run cases/demo.xlsx --case-id user.get --profile live --run-mode read     # 比对基线
CONFIRM_BASELINE=1 easytest run cases/demo.xlsx --case-id user.get --profile live --run-mode baseline
easytest snapshot check --root .
easytest snapshot maintain --root . --keep-failed 1
```

## 9. 接入 CI 与日常维护

```bash
python -m pip install vendor/easytest-0.4.2-py3-none-any.whl
easytest compile cases --check
python -m pytest test_cases.py --profile live --run-mode read --easytest-root . --easytest-report artifacts/report.html --junitxml=artifacts/junit.xml
```

日常提交维护后的 XLSX 及其同名 JSON。

## 10. 扩展适配器

- **Database**：在 `runtime.json` 定义连接，在 `operations.json` 配置参数化 SQL，`allow_db_write` 控制写权限。
- **RPC / UI / Scenario**：在独立安装包实现业务 handler 并配置到测试环境中，参考 [独立业务 handler 示例](../examples/business_handler/README.md)。
